# fw_1541 deviation register

Core 1 ("1541" drive) firmware of IronKernel 64. This register lists every
place where the firmware departs from vendor or third-party code as shipped,
or from a rule of `embedded_ccoding.md`. Each site carries the literal tag
`IK64_DEVIATION <n>`, so `grep -rn IK64_DEVIATION fw_1541` gives the complete
map. Unmodified third-party trees (`third_party/libsmb2`,
`third_party/freertos`, the AMD lwIP 2.2.0 install) carry no tags; nothing
in them is edited. Each deviation is a build flag, a configuration header, or
a project file that stands in for a vendor file.

Third-party versions: libsmb2 commit `a52c1571` (`third_party/libsmb2/SOURCE.txt`),
FreeRTOS-Kernel V11.3.3 (`third_party/freertos/SOURCE.txt`), lwIP 2.2.0 from
`C:\AMDDesignTools\2026.1\Vitis\data\embeddedsw\ThirdParty\sw_services\lwip220_v1_4`.

| 2 | `src/smb_alloc.c`, `src/smb_alloc.h` | libsmb2 allocates with `malloc`/`calloc`/`realloc`/`free` and newlib `strdup`/`asprintf` (585 source lines in `lib/` outside the Kerberos wrapper, `grep -c`). newlib's allocator grows a heap through `_sbrk`. | `smb_alloc.c` defines `malloc`, `free`, `calloc`, `realloc` and newlib's `_malloc_r`, `_free_r`, `_calloc_r`, `_realloc_r` over 8 fixed-size classes of static blocks (32 B to 72 KiB; 999,424 B in `.bss` in the DDR3 partition). Oversize requests and empty classes are rejected (NULL, logged, counted). A foreign pointer or a double free fail-stops. The link map shows that newlib's `malloc`, `__malloc_av_` and `_sbrk` are not linked. | Deviation from the no-heap rule (`embedded_ccoding.md` section 6). libsmb2 has no allocator hook, and its PDUs (6,392 B), context (4,200 B) and directory listings (112 B per entry plus the name) are runtime-variable. The pool bounds them with no fragmentation. Class sizes come from rv32 `sizeof` measurements and the receive-path analysis in `smb_alloc.c`. The first board session confirms them with `smb_alloc_log_stats()`. |
